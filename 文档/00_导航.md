# Venera 项目文档导航（操作前先看这里）

> 三份文档加起来 500+ 行，**不需要全读**。先按下面的任务类型找到自己的路径，
> 只看对应文档和章节即可，其余明确跳过。

---

## 你是哪种任务？

### 🅰 只改书源（book source/*.js，不 build、不 push 代码）

- **必读**：`COMIC_SOURCE_DEV.md`（全书，147 行）
- **唯一提交注意**：书源 js 是本地私有内容，**不要 push 进仓库** → `GIT_WORKFLOW.md` 第 2.1 节
- **不用看**：`BUILD_NOTES.md` 全文 —— 书源开发与构建 / 版本号 / CI 完全无关，跳过
- 不碰 lib/ 代码、不 build exe、不发版 → 不需要了解任何构建知识

### 🅱 改 App 代码（lib/*.dart）+ 要 build Windows exe

- **必读**：`BUILD_NOTES.md` 以下章节：
  - 第 1 节（只能 build exe，APK 走 CI）
  - 第 3 节（禁止操作 + 中国镜像坑）
  - 第 4 节（FRB 报错诊断）
  - 第 8 节（build-win.bat 用法）
  - 第 10、11 节（SDK 目录 / 离线构建坑）
  - 文末「开发者偏好速查」（代码风格约定）
- **提交前必读**：`GIT_WORKFLOW.md` 第 1 节（push 走代理）+ 第 2 节（提交规则）
- **可跳过**：`COMIC_SOURCE_DEV.md`（除非本次改动涉及书源相关代码）

### 🅲 发版 / 打 tag / 手动取 APK / CI 失败排查

- **必读**：`GIT_WORKFLOW.md` 全文（push / 提交 / 跳过 CI / 发版全流程）
- **必读**：`BUILD_NOTES.md` 第 2 节（版本号规则，发版必改两处）+ 第 5 节（CI analyze 诊断）
- **可跳过**：`COMIC_SOURCE_DEV.md`

## 三份文档一句话速查

| 文档 | 讲什么 | 谁要看 |
|---|---|---|
| `BUILD_NOTES.md` | 本地构建 exe、版本号、环境坑、代码规范 | 改 App 代码 / 发版的人 |
| `COMIC_SOURCE_DEV.md` | 书源 JS 开发（引擎 API、解析、解密） | 只写书源的人 |
| `GIT_WORKFLOW.md` | push、提交规则、CI 跳过/触发、Release | 任何要提交 / 发版的人 |

## 通用底线（谁都适用）

- 输出文件 UTF-8 **无 BOM**（`BUILD_NOTES.md` 第 9 节）
- 书源相关内容**永不写进根目录 README.md**（`BUILD_NOTES.md` 第 7 节）
